# 写操作与提交功能

GitHub1s 现在支持写操作！您可以直接在浏览器中编辑文件并将更改提交到 GitHub 仓库。

## 功能特性

### 文件操作

- **创建文件**：在仓库中创建新文件
- **编辑文件**：修改现有文件
- **删除文件**：从仓库中删除文件
- **重命名文件**：重命名或移动文件
- **复制文件**：复制文件
- **创建目录**：创建新文件夹

### 提交和推送

所有本地更改都会被跟踪，并且可以直接从 VS Code 界面提交到 GitHub。

## 使用方法

### 1. 编辑文件

只需打开任何文件并开始编辑。您的更改将在本地被跟踪。

### 2. 查看本地更改

- 打开**源代码管理**面板（Ctrl+Shift+G）
- 您将看到一个名为"GitHub1s Local Changes"的新部分
- 这显示了所有已修改或删除的文件

或者，使用命令面板（Ctrl+Shift+P）并运行：

- `GitHub1s: Show Changes Summary`

### 3. 提交更改

有几种方式可以提交您的更改：

#### 方式 1：源代码管理面板

1. 打开源代码管理面板
2. 在输入框中输入您的提交消息
3. 按 Ctrl+Enter 或点击提交图标

#### 方式 2：命令面板

1. 打开命令面板（Ctrl+Shift+P）
2. 运行 `GitHub1s: Commit and Push Changes`
3. 输入您的提交消息
4. 选择是提交到当前分支还是创建新分支

### 4. 创建新分支

在提交之前，您可以创建一个新分支：

1. 打开命令面板（Ctrl+Shift+P）
2. 运行 `GitHub1s: Create New Branch`
3. 输入新分支名称
4. 分支将从您当前的位置创建

### 5. 丢弃更改

要丢弃所有本地更改：

1. 打开命令面板（Ctrl+Shift+P）
2. 运行 `GitHub1s: Discard Local Changes`
3. 确认操作

## 身份验证

要使用写操作，您必须通过 GitHub 进行身份验证：

1. 您需要一个具有适当权限的 GitHub 个人访问令牌
2. 令牌必须具有 `repo` 范围才能写入仓库
3. 您只能写入您有推送权限的仓库

## 可用命令

| 命令                                | 描述               | 快捷键 |
| ----------------------------------- | ------------------ | ------ |
| `GitHub1s: Commit and Push Changes` | 提交并推送本地更改 | -      |
| `GitHub1s: Create New Branch`       | 创建新分支         | -      |
| `GitHub1s: Discard Local Changes`   | 丢弃所有本地修改   | -      |
| `GitHub1s: Show Changes Summary`    | 查看本地更改摘要   | -      |

## 工作原理

### 本地更改跟踪

当您修改、创建或删除文件时：

1. 更改存储在浏览器本地
2. 原始文件内容从 GitHub 缓存
3. 修改的内容保存在单独的缓存中
4. 所有更改都会反映在源代码管理面板中

### 提交过程

当您提交更改时：

1. 为每个修改的文件在 GitHub 中创建一个 blob
2. 创建一个包含所有更改的新树
3. 创建一个引用新树的提交
4. 更新分支引用以指向新提交
5. 成功提交后清除本地更改

## 限制

- 写操作仅支持 GitHub 平台（github1s）
- 您必须具有适当的仓库权限
- 更改保存在浏览器内存中，直到提交
- 刷新浏览器将丢失未提交的更改
- 大文件上传可能受到 GitHub API 限制

## 示例

### 示例 1：编辑并提交

```
1. 打开一个文件（例如 README.md）
2. 做一些更改
3. 按 Ctrl+Shift+G 打开源代码管理
4. 输入 "更新 README"
5. 按 Ctrl+Enter 提交
6. 选择"当前分支"
```

### 示例 2：创建文件并提交到新分支

```
1. 创建一个新文件（文件 > 新建文件）
2. 保存并命名
3. 按 Ctrl+Shift+P
4. 运行 "GitHub1s: Commit and Push Changes"
5. 输入提交消息
6. 选择"新分支"
7. 输入分支名称（例如 "feature/new-file"）
```

## 故障排除

### "没有此操作的权限"

- 确保您已使用有效的令牌进行身份验证
- 验证您的令牌具有 `repo` 范围
- 检查您是否有仓库的写入权限

### "提交失败"

- 检查您的网络连接
- 验证分支名称是否有效
- 确保您没有在没有适当权限的受保护分支上工作

### 刷新后更改消失

- 未提交的更改存储在浏览器内存中
- 始终在刷新页面之前提交更改
- 考虑为大型工作流使用 `git stash` 概念

## 技术细节

写功能使用以下技术实现：

- GitHub 的 Git Data API 用于创建 blob、树和提交
- VS Code 的 FileSystemProvider API 用于文件操作
- 自定义源代码管理集成用于跟踪更改
- 使用 Octokit 的 GitHub REST API 进行身份验证和 API 调用
